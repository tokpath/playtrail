# PlayTrail 视觉与交互设计规范

> 审美负责人：Opus。实现者必须按本规范实现；规范没写到的地方，选择**更克制**的方案，并在交付报告里列出。验收时逐项对照本文截图检查。

## 1. 设计概念：网页游戏的"野外指南"

PlayTrail 不是又一个霓虹暗黑的游戏门户。它像一本做工考究的**户外步道指南**：米色纸张、墨色文字、等高线地图、步道标记和一条橙色的路线。用户沿着"路线"一站一站发现游戏。

三个关键词：**可信**（像指南一样克制、信息清楚）、**有路感**（路线、站点、等高线贯穿全站）、**好玩**（生成封面色彩丰富、微动效轻快）。

反面清单（出现即返工）：紫色渐变 + 白卡片的模板感、霓虹发光、玻璃拟态、满屏阴影、emoji 当图标、库存插画、居中大标题 + 三栏功能卡的落地页套路、所有元素同一圆角同一阴影。

### 2.3 字体

- 展示字体：**Bricolage Grotesque**（`next/font/google`，自托管，变量字体，Latin 子集，`display: swap`），用于 h1–h3、卡片游戏名、大数字、封面字母。字距 `-0.02em`（≥36px 时 `-0.03em`），字重 600–800。
- 正文：`ui-sans-serif, system-ui, -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。中文标题也回落到这一栈（展示字体只覆盖拉丁字符，浏览器会自动混排）。
- 标签字体（"野外笔记"）：`ui-monospace, "SF Mono", Menlo, monospace`，11–12px，大写，字距 `0.08em`，用于元数据标签、时间戳、计数、位置编号。
- 字号阶梯：12 / 14 / 16 / 18 / 22 / 28 / 36 / 48 / 64；首页主标题 `clamp(40px, 6vw, 72px)`，行高 1.02。正文 16px / 1.6，中文正文行高 1.75。正文最大宽度 68ch。

### 2.4 间距、圆角、阴影、动效

- 4px 基准：4 8 12 16 24 32 48 64 96。区块之间纵向 64（移动端 48）。
- 内容最大宽 1240px，左右 24px（≤640px 时 16px），12 栏，栏间距 24px。
- 圆角：卡片和面板 16px；封面 12px；输入框 12px；Chip 和小徽标 999px；CTA 按钮 14px。
- 阴影：默认**不用**阴影，靠 1px hairline 描边分层。只有悬停卡片：`0 18px 32px -18px rgb(27 26 23 / .35)` 加 `translateY(-3px)`。
- 动效：180ms `cubic-bezier(.2,.7,.2,1)`；封面悬停时等高线层平移 6px（视差感）；路线虚线在进入视口时 `stroke-dashoffset` 动画一次（600ms）。`prefers-reduced-motion: reduce` 时全部关闭。
- 焦点：`outline: 2px solid var(--trail); outline-offset: 3px`，所有可交互元素一致。

## 3. 标志性元素（全站复用）

1. **路线（Trail line）**：SVG 虚线路径，2px，`stroke-dasharray: 2 7`，圆头，trail 色；连接站点标记。用在首页"今日路线"、详情页"下一站"标题旁、空状态插图。
2. **站点标记（Stop marker）**：28px 圆，ink 填充，paper 色等宽数字；当前项 trail 填充 + trail-ink 数字。用于精选顺序、热门位置、分页当前页。
3. **票根（Ticket stub）**：热门快照的采集信息，像步道票根：左右两侧半圆缺口（CSS mask），虚线分隔，等宽字体，例如 `COLLECTED 2026-11-08 16:21 UTC+8 · TW · PAST 24H RISING`。历史快照时变成 amber 描边并显示"历史快照，已超过 48 小时未更新"。
4. **野外笔记面板（Field notes）**：详情页的事实区。两列 `dt/dd`，dt 用等宽大写小标签，dd 用正文；每行 hairline 分隔；未核实的值用 ink-muted 斜体并带一个空心圆点 `○ 待核实`，已核实用实心 moss 圆点 `● 2026-11-08`。
5. **等高线纹理**：生成封面和类别横幅用的同一套等高线算法（§5），保证全站视觉同源。
6. **路标 Chip（Trail sign）**：类别入口：8px 类别色点 + 名称 + 等宽计数，hairline 描边，悬停时描边变 ink。

## 4. 组件规范

### 4.1 Header

- 高 64px，paper 背景，底部 hairline；滚动后背景加 `backdrop-filter: saturate(1.2) blur(8px)` 和 90% 不透明度（仅此一处用模糊）。
- 左：Logo = 一个 18px 的"路线节点"符号（两个圆点 + 一段虚线，SVG）+ 文字 `PlayTrail`（展示字体 700）；中文界面 Logo 后加 `游引`（ink-muted，14px）。
- 中（≥1024px）：搜索框，宽 420px，`surface-sunk` 背景，左侧放大镜图标，右侧 `↵` 提示；提交按钮对屏幕阅读器可见（视觉上是图标按钮）。
- 右：语言切换（地球图标 + 当前语言自称，下拉列出已上线语言的自称；当前项打勾）。
- 第二行（≥768px）：类别路标横向列表（只显示有内容的类别），可横向滚动、两端渐隐遮罩；当前类别实心 ink 背景 + paper 文字。
- 移动端：搜索收起为图标，点击展开为整行输入框；类别行保留横向滚动。

### 4.2 GameCard（核心组件）

```
┌───────────────────────────┐
│  [生成封面 / 授权封面 16:9] │  圆角 12，内部右下角的大字母被裁切
│  ◖ .io                     │  左上角：paper 90% 小药丸，类别名（等宽 11px）
└───────────────────────────┘
  EvoWars.io                    展示字体 20px/600，单行省略
  Evolve your warrior by…       ink-muted 14px，两行截断
  ● 多人   ● 竞技                 最多 3 个标签，等宽 11px，ink-muted
```

- 整张卡是一个链接（`<a>` 包裹，内部无其他可点击元素）；卡片本身无背景无描边，封面带 hairline 描边；悬停：封面上浮 3px + 阴影 + 等高线层平移，游戏名下划线（trail 色 2px，offset 4px）。
- `outboundAllowed=false` 时封面左上角药丸换成 signal 描边的 `链接暂不可用`。
- 尺寸变体：`lg`（今日路线主卡，标题 32px，摘要 3 行，带"查看详情 →"）、`md`（默认）、`row`（热门榜和相关游戏的横排：封面 120px 宽在左，文字在右）。

### 4.3 按钮

- **Primary CTA**（仅详情页"在 CrazyGames 游玩 ↗"）：高 56px，左右 28px，trail 背景，trail-ink 文字 17px/700，14px 圆角；悬停背景加深 6%、箭头右上移 2px；按下 `scale(.98)`。禁用时：surface-sunk 背景、ink-muted 文字、删除箭头，文字改为"外部链接暂不可用"。
- Secondary：hairline 描边，ink 文字，高 44px。
- Ghost：仅文字 + 下划线悬停。
- 全部最小点击区域 44×44。

### 4.4 表单控件

- 输入框：高 48，surface-sunk 背景，无描边，聚焦时 2px trail 环。
- 排序：分段控件（两个选项），选中项 surface 背景 + hairline 描边 + ink 文字。
- 筛选 Chip：未选 hairline 描边；选中 ink 背景 paper 文字，右侧 `×`。

### 4.5 空状态与错误

都用同一个小插图：一段等高线 + 断开的路线 + 路牌（SVG，ink 线条 + trail 点缀），配一句有个性但清楚的文案：
- 无结果："这条路上没有找到游戏" / "No games on this trail" + 当前条件 + 清除按钮 + 回首页。
- 404："路线到此为止" / "This trail ends here"。
- 410："这款游戏已从本站下架" / "This game has left the trail"。
- 列表加载失败：signal 色小字 + "重试"按钮。

## 4.6 真实封面（CrazyGames 图片）〔2026-11-08 新增〕

游戏卡片、详情大图、首页拼贴和热门列表优先显示真实封面（PRD 22.12）。真实封面色彩饱和、信息密集，规范如下：

- **组件 `GameCover`**：外层固定 16:9、圆角 12、hairline 描边；底层始终渲染 TrailCover，上层是 `<img srcset sizes>`，加载完成后 160ms 淡入（减少动效时直接显示）。加载失败就移除 `<img>`，露出 TrailCover。
- **不加任何滤镜或叠色**，保持原图色彩。类别药丸改为不透明的 surface 底色 + hairline 描边，在任何图上都清晰。
- 悬停：图片 `scale(1.03)`（容器 `overflow: hidden`），配合卡片上浮；等高线视差只用在 TrailCover 上。
- 首屏主图（今日路线主卡、详情大图）`loading="eager"`、`fetchpriority="high"`；其余 `lazy`。`sizes` 按网格实际宽度填写（例如 md 卡 `(min-width:1024px) 300px, (min-width:640px) 45vw, 100vw`）。
- 类别横幅、空状态和 404 仍使用生成图形，保持站点自身的视觉识别；真实封面只代表游戏本身。
- 因为真实封面已经很抢眼，卡片外的装饰更要克制：不要再给卡片加彩色背景或渐变。

## 5. 生成封面（TrailCover）算法

纯函数组件 `TrailCover({ slug, category, name, size })`，服务端渲染内联 SVG，`viewBox="0 0 320 180"`，`role="img"` 时 `aria-label` 为空字符串并 `aria-hidden="true"`（卡片已有文字标题）。**同一 slug 在任何地方渲染结果完全一致。**

1. 种子：`seed = fnv1a32(slug)`，PRNG `mulberry32(seed)`；所有随机数按固定顺序取用。
2. 背景：`linearGradient`，角度 `110° + rand*60°`，从类别 `base` 到 `deep`；再叠一层中心在随机点的 `radialGradient`（白色 0.18 → 0）作为"光照"。
3. 等高线：中心 `(cx, cy)` 在 `x∈[40%,90%]`、`y∈[20%,80%]`；画 9 条闭合路径，半径从 18 递增约 22，每条用 24 个点的极坐标，半径加 `sin` 叠加扰动（2 个频率，振幅为半径的 6–12%，相位随机），用 Catmull-Rom 转三次贝塞尔得到平滑曲线。描边 paper 色，`stroke-width 1.1`，透明度从内到外 `0.38 → 0.12`。
4. 路线：一条从左边缘到右边缘的三次贝塞尔（控制点随机），`stroke-dasharray: 2 6`，paper 色 0.85，圆头；在路线 60% 处放一个 7px 的 trail 色圆点 + 2px paper 描边（"你在这里"）。
5. 字母：取游戏名的首个字母或数字（去掉开头的冠词 "The"），用展示字体 800，字号 170，放在右下，`x = 320 - 0.55*字宽`，`y = 205`（故意被裁掉一部分），paper 色 0.92，`mix-blend-mode: soft-light` 不可用时退化为 0.85 透明度。
6. 噪点：一个固定的 `feTurbulence` 滤镜（baseFrequency .9，透明度 .06）叠加，增加纸张质感（同一个 `<filter>` 定义全页共享，id 唯一）。

类别横幅（类别页顶部）复用同一算法，`viewBox="0 0 1240 280"`，种子为类别 slug，不画字母，左侧放类别名大字（HTML 文本，不在 SVG 内）。

默认分享图（`opengraph-image`，1200×630）：左 60% 为该游戏的 TrailCover（放大重算），右 40% 为 paper 背景 + 游戏名（展示字体 64px）+ 类别 + "PlayTrail" 小标；首页/类别页用站点版（路线 + Logo + 标语）。

## 6. 页面构成

### 6.1 首页 `/{locale}/`

1. **开场区**（不是满屏 Hero）：左 7 栏 —— 等宽小标签 `A FIELD GUIDE TO BROWSER GAMES` / `网页游戏野外指南`；主标题 en "Find the next game you can't put down." / zh "发现下一款让你上头的游戏"；一行副标题 "Hand-picked browser games, honest notes, one click to play on CrazyGames." / "人工精选的网页游戏，实在的说明，一键前往 CrazyGames 开玩。"；下方大号搜索框（高 56）。右 5 栏 —— 一个由 5 个最新精选游戏的**小封面沿路线排布**的拼贴（封面 96px 圆角 10，被一条 trail 虚线依次串起，带站点编号 1–5），桌面端轻微错落；移动端隐藏这块。底部一行统计：`{n} GAMES · {m} CATEGORIES · UPDATED {date}`（等宽，ink-muted），数字只来自真实数据。
2. **今日路线 Today's trail**（编辑精选 ≤12）：标题左侧一个站点标记 `01`。第 1 款用 `lg` 卡占 7 栏；右侧 5 栏是第 2–5 款的 `row` 卡，竖向排列，左侧有一条竖向路线串起站点标记 2–5。其余精选（6–12）在下方 4 栏网格（平板 2 栏、手机 1 栏）。精选为 0 时整块隐藏。
3. **CrazyGames 热门快照**：标题 + 票根（采集时间、地区、定义）。下方横向可滚动的 `md` 卡列表，每张卡左上角叠一个大号空心位置数字（展示字体 64px，`-webkit-text-stroke: 1.5px ink`，透明填充），右侧"查看全部 →"。stale 或无快照时整块隐藏。
4. **按类别走 Browse by category**：网格 3/4 栏，每个类别是一个 16:7 的小横幅（等高线算法 + 类别色），左下类别名（展示字体 22px，paper 色）+ 等宽计数。只显示有内容的类别。
5. **Footer**：surface 背景，上沿是一条横贯全宽的路线虚线；三栏：品牌与一句定位、站点链接（关于 / 隐私 / 版权与纠错）、语言切换；底部小字："PlayTrail 是独立的精选导流站，与 CrazyGames 无官方合作。游戏内容、广告与可用性由 CrazyGames 提供。"

### 6.2 列表 `/{locale}/games`

- 顶部：标题 "All games / 全部游戏" + 结果数（等宽）。
- 桌面：左 3 栏筛选侧栏（类别列表带色点和计数，单选；标签 Chip 云，单选；"清除全部"），右 9 栏：搜索框 + 排序分段控件，生效筛选 Chip 行，3 栏卡片网格，底部分页（站点标记风格的页码，当前页 trail）。
- 移动：筛选收进"筛选"按钮打开的底部抽屉（全屏高 85%，可键盘关闭，焦点陷阱）。
- 筛选/排序/分页全部写进 URL，用 `<Link>` 和 `router.push`，浏览器后退恢复。

### 6.3 详情 `/{locale}/games/{slug}`

- 面包屑（等宽小字）：首页 › 类别 › 游戏。
- 上部双栏：左 7 栏大封面（授权封面或 TrailCover `lg`）；右 5 栏：类别路标、游戏名（展示字体 48px）、别名（若有，ink-muted）、一句话说明（20px）、标签 Chip、**Primary CTA**、CTA 下方 13px 说明（新标签页打开外部平台…），再下面一行 ink-muted 小字元数据（`● 核实于 2026-11-08 · CrazyGames`），不再放迷你野外笔记，避免与下方完整面板重复（UI 审核 r1 U5）。
- 下部：左 7 栏"简介"（正文，按换行分段）与"操作"（每行 `键：动作` 渲染为两列，键用 `<kbd>` 样式：surface-sunk 背景、hairline 描边、等宽）；右 5 栏完整野外笔记面板（开发商、设备适配及证据、来源与核实时间、首次收录、外部平台）。截图（若有）在简介下方横向滚动。
- **下一站 Next stops**（相关游戏 ≤6）：标题旁一小段路线；桌面 3 栏 × 2 行 `md` 卡；没有时隐藏。
- CTA 可用时在移动端底部固定一条 CTA 栏（滚过主 CTA 后出现，带 safe-area padding）。

### 6.4 热门 `/{locale}/hot`

标题 "CrazyGames Hot Snapshot / CrazyGames 热门快照"、定义说明、票根。列表为竖排 `row` 卡，左侧大号空心位置数字（保留原始位置，缺号就跳过，不重排）。历史快照：票根变 amber + 顶部 amber 提示条。无快照：空状态插图 + "浏览全部游戏"。

### 6.5 类别 `/{locale}/categories/{slug}`

顶部类别横幅（§5），上面叠类别名（展示字体 56px，paper 色）和计数；下面复用列表组件（不显示类别筛选）。空类别：横幅 + 空状态 + noindex。

### 6.6 关于 / 隐私 / 版权

单栏 68ch 长文排版：等宽小标签 + 大标题 + 正文；小标题之间 48px；首段 20px。页面顶部一个细长等高线条带（高 64，ink 线条 8% 透明度）。法律页内容不确定的段落用 amber 左边框的提示块标"待需求方确认"。

### 6.7 后台 `/admin`

- 风格：同一套令牌，信息密度更高；正文 14px；不使用生成封面大图（列表里用 40×22 的小封面）。
- 布局：左侧 232px 侧栏（Logo + 导航：概览、游戏、来源目录、变更待复核、热门快照、导入、字典、统计、爬虫、操作记录），右侧内容区最大 1280。
- 表格：表头等宽 11px 大写，行高 52，hairline 分隔，悬停 surface-sunk；状态用小药丸：draft（hairline 描边）、published（moss 浅底）、unlisted（ink-muted 浅底）、suspect/invalid（signal 浅底）、pending（amber 浅底）。
- 游戏编辑页：顶部状态条（状态药丸、链接状态、revisionVersion、"有待发布修改"）；主体左侧表单分区（基本信息 / 分类标签 / 设备与来源 / 素材 / 编排），语言用 Tab（en / zh，Tab 上显示审核状态点）；右侧固定的"发布门禁"清单（每项 ✓/✗ 与原因，实时来自 `/gates`）和操作按钮（保存、审核通过、发布、预览、下架、关闭 CTA）。危险操作用确认对话框并要求填写原因。
- 来源目录：表格 + 右侧抽屉显示参考字段（CrazyGames 描述等仅供参考，抽屉顶部 amber 提示"以下内容版权属于原作者，仅供核对事实，不得复制或翻译后发布"）。

## 7. 文案语气

- 英文：简洁、友好、具体，第二人称；避免营销夸张。中文：口语、利落，不用"重磅""爆款"等词。
- CTA 与离站说明、热门定义、页脚声明的文字必须与 PRD 第 05 节一致。
- 所有界面文案放在 `messages/en.json`、`messages/zh.json`；两者键完全一致。

## 8. 响应式断点与验收视口

断点：`sm 640`、`md 768`、`lg 1024`、`xl 1280`。验收视口：360、390×844、768、1280、1440。任何视口不得出现横向溢出；首页、列表、详情在 390 宽时依然要"好看"——生成封面清晰、标题不拥挤、CTA 一屏内可见。

## 9. 审美验收清单（Opus 逐项打勾）

1. 首屏有明确的视觉主角（开场区路线拼贴或今日路线主卡），而不是平均分布的卡片墙。
2. trail 橙色只出现在行动与路线上，没有被滥用。
3. 生成封面彼此可区分、同类别色调一致、字母裁切自然，暗色模式下仍好看。
4. 字体层级清楚：展示字体只用于标题和数字；等宽字体只用于元数据。
5. 留白节奏一致（区块 64 / 48），对齐到 12 栏网格。
6. 悬停、焦点、按下、禁用、加载、空、错误状态都设计过。
7. 中英文两种语言下排版都不破（中文更短/更长都要检查）。
8. 暗色模式完整（无遗漏的硬编码颜色）。
9. 无模板感、无反面清单中的任何元素。
