## 02 产品定位与成功口径

1. **定位〔v1.1 修订〕**：帮助全球网页游戏玩家用较少的步骤，按自己的语言发现适合自己的网页游戏，再跳转到 CrazyGames 上对应的游戏页。游戏名保留官方英文名，各语言的描述都由本站原创编写（翻译也要经过人工审核）。
2. **目标用户**：想快速找游戏的访客（P0 语言为英文和简体中文）；负责选品、整理信息、维护链接的单一管理员。访客不需要注册、登录或提交个人资料。
3. **价值**：清晰的主类别、玩法标签、简短的原创说明、可信的来源日期、明确的离站按钮，以及**可解释的相关推荐〔v1.1 新增〕**。不承诺游戏质量、地区可用性或适龄等级。
4. **核心路径**：首页或列表 → 分类 / 关键词筛选 → 游戏详情 →（可选）相关游戏 → 在 CrazyGames 上游玩。游戏启动、广告、账号和存档都在外站完成。
5. **非目标**：自托管游戏、iframe 播放、游戏 SDK、抓包或逆向内部 API、下载站、支付、评论评分、社交、**基于用户行为或画像的个性化推荐〔v1.1 明确〕**、平台分成或官方合作承诺。

**一期建议成功口径**：按语言分别统计已审核的可用游戏数、详情浏览次数、离站点击次数、详情页离站点击率、相关推荐点击次数〔v1.1 新增〕、失效链接数和内容更新时间。暂不设未经验证的增长目标，上线后先积累基线。

- 详情页离站点击率 = 详情 CTA 点击事件数 / 详情浏览事件数。它不是实际开玩转化率，也不等于独立访客转化率。
- 相关推荐点击率 = 相关推荐卡片点击事件数 / 展示相关模块的详情浏览事件数〔v1.1 新增〕。

本站只凭外链点击无法拿到 CrazyGames 的真实开玩、时长、留存或收入数据。平台没有公开每款游戏的游玩量，不得自行补造玩家数、评分、增长率或收入预测。

## 04 用户流程与信息架构

1. **访客发现**：进入首页，看编辑精选和带日期的热门快照；卡片默认进入本站详情页，不自动跳转外站。
2. **缩小范围**：选择一个主类别、一个玩法标签，或输入关键词；组合筛选后保留 URL 状态，可以复制链接，浏览器返回时恢复。
3. **了解游戏**：查看原创简介、已核实的玩法 / 操作、来源和核实日期；设备信息没有经过实测时显示"设备适配未确认"。
4. **继续发现〔v1.1 新增〕**：在详情页底部看"相关游戏"，点击后进入另一款游戏的本站详情页。
5. **离站游玩**：点击标明外部平台的 CTA，在新标签页打开 CrazyGames 对应游戏页；本站保留当前详情页。
6. **切换语言〔v1.1 新增〕**：通过页头语言切换器切到同一页面的其他语言版本；目标语言没有该页面时，进入目标语言首页。
7. **管理员维护**：认证后进入后台，导入或新增草稿，补充各语言的原创内容和素材权利记录，预览，审核，手动发布。链接失效时关闭 CTA 或下架。

### 4.1 路由〔v1.1 修订：加语言前缀〕

`{locale}` 取值来自配置 `SUPPORTED_LOCALES`，P0 为 `en`、`zh`。

| 建议路由 | 职责 |
| --- | --- |
| `/` | 不渲染内容，按请求头 `Accept-Language` 302 到 `/{locale}/`，规则见第 4.2 节。hreflang 的 `x-default` 指向这里 |
| 不带语言前缀的公开路径〔v1.1 新增〕，如 `/games/{slug}`、`/games?q=…`、`/categories/{slug}`、`/hot`、`/about` | 不渲染内容，按 `Accept-Language` 302 到 `/{locale}` + 原路径 + 原 query，规则见第 4.2 节。用于分享、外部链接或手输地址时自动进入访客的语言 |
| `/{locale}/` | 首页：编辑精选、有效热门快照、有效分类 |
| `/{locale}/games?q=&category=&tag=&sort=&page=` | 全量游戏搜索与筛选列表 |
| `/{locale}/categories/{slug}` | 单个类别的落地页，复用列表能力 |
| `/{locale}/games/{slug}` | 游戏详情，地址稳定且唯一；slug 全局唯一，不随语言变化 |
| `/{locale}/hot` | 热门快照列表，标注采集时间、采集地区和定义 |
| `/{locale}/about`、`/{locale}/privacy`、`/{locale}/copyright` | 本站定位、隐私说明、版权与纠错联系方式（每种语言一份） |
| `/admin/*` | 单管理员管理区，不带语言前缀，界面只做中文，不被搜索引擎索引 |
| 不支持的 `{locale}` 或其他地址 | 真实 HTTP 404，页面提供返回入口（文案按 `Accept-Language` 选择语言） |

### 4.2 按请求头 `Accept-Language` 跳转〔v1.1 新增〕

语言由浏览器请求头 `Accept-Language` 决定，服务端完成跳转，前端不做二次跳转。

**触发范围**

- 只对**不带语言前缀**的公开 GET / HEAD 请求生效（第 4.1 节的 `/` 和\"不带语言前缀的公开路径\"）。
- 已经带合法前缀的地址（如 `/zh/games/x`）**一律不按请求头跳转**，直接按 URL 的语言渲染。URL 是用户或搜索引擎的明确选择，否则会出现\"点了 English 又被跳回中文\"和搜索引擎抓不到非英文页的问题。
- `/admin/*`、`/api/*`、静态资源、`/robots.txt`、`/sitemap*.xml` 不跳转。
- 不带前缀的路径如果去掉前缀后也不是合法路由，直接 404，不先跳转再 404。

**匹配算法**

1. 解析 `Accept-Language`，按 q 值降序（q 相同时保持原顺序），忽略 `q=0` 和 `*`；格式非法的项跳过，整个头非法时视为没有该头。
2. 依次取每一项，与**已上线语言**（`SUPPORTED_LOCALES` 中达到上线门槛的语言，见第 03 节）比对，命中第一个就停止：
   - 先精确匹配完整标签（不区分大小写），例如以后上线 `pt-BR` 时 `pt-BR` 命中 `pt-BR`；
   - 再按主语言匹配，例如 `en-US`、`en-GB` → `en`；`zh-CN`、`zh-SG`、`zh-Hans` → `zh`。
3. 中文特殊规则：P0 只有简体，`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` 也匹配到 `zh`（对繁体用户来说简体比英文更易读）。以后 `zh-Hant` 上线后，这些标签改为优先匹配 `zh-Hant`。
4. 都没有命中，或请求没有 `Accept-Language`（大多数搜索引擎爬虫属于这种情况）时，使用默认语言 `en`（可配置 `DEFAULT_LOCALE`）。

**响应要求**

- 状态码用 **302**，不用 301，避免浏览器和 CDN 把某一种语言的跳转结果永久缓存给所有人。
- 响应头带 `Vary: Accept-Language`。CDN 如果不能按 `Accept-Language` 分别缓存，这类跳转响应必须 `Cache-Control: private, no-store`，或在边缘函数里计算，不能把一个访客的跳转结果缓存给其他人。
- `Location` 保留原路径和完整 query，只在前面加语言前缀，例如 `/games?q=car&page=2` → `/zh/games?q=car&page=2`。
- 不写 cookie，不读 IP 或地理位置，不记住上次选择；P0 只靠 URL 和请求头决定语言。
- 跳转只发生一次，不能出现跳转循环。

**与语言切换器的关系**

- 用户通过页头切换器选择语言时，直接链接到 `/{目标语言}/…`，带前缀的地址不会再被请求头改写，所以用户的选择总是生效。
- 由于 P0 不记住选择，用户下次访问不带前缀的地址（例如直接打开 `/`）时，仍按浏览器语言跳转；这是有意的取舍，需求方如果希望记住选择，可以在 P1 增加一个只存语言的第一方 cookie，并在隐私页写明。

**示例**

| 请求 | `Accept-Language` | 结果 |
| --- | --- | --- |
| `GET /` | `zh-CN,zh;q=0.9,en;q=0.8` | 302 → `/zh/` |
| `GET /` | `fr-FR,fr;q=0.9,en;q=0.5` | 302 → `/en/`（法语未上线，命中第二项 `en`） |
| `GET /` | `ja` | 302 → `/en/`（未命中，用默认语言） |
| `GET /` | 无 | 302 → `/en/` |
| `GET /games/evowars-io` | `zh-TW` | 302 → `/zh/games/evowars-io` |
| `GET /games?q=car&page=2` | `en-US` | 302 → `/en/games?q=car&page=2` |
| `GET /zh/games/evowars-io` | `en-US` | 200，按中文渲染，不跳转 |
| `GET /zh/` | 任意 | `zh` 尚未达到上线门槛时仍是 200，但 noindex（第 03 节），不跳转 |
| `GET /foo` | 任意 | 404 |

一期建议不单独建标签的 SEO 落地页，标签通过列表参数筛选。后台认证由实现方选成熟方案，不限定技术栈；本文只是需求文档，不包含可用的后台或登录表单。

### 5.1 异常与边界状态

1. **空结果**：显示"未找到符合条件的游戏"、当前条件、清除筛选按钮和首页入口；不伪装成有结果。已知类别但当前语言下没有已发布游戏时，返回可解释的空目录页，HTTP 200 且 noindex；导航和 sitemap 都不列入。未知类别返回 404。
2. **图片缺失 / 加载失败**：立即回退到本站自制的通用占位视觉；预留相同宽高比，避免页面跳动。占位图不包含第三方 logo，也不复制游戏美术。
3. **已知失效链接**：详情页显示"外部链接暂不可用"，禁用 CTA，并提供返回列表的入口；不自动换成其他游戏。只凭 HEAD 失败、超时或 403 不足以判定游戏已下架，标记为待核实。
4. **下架**：从公开列表、搜索和热门视图中立即移除；原详情页返回 410 和"该游戏已从本站下架"，不提供 CTA，不被索引。草稿和不存在的 slug 都返回 404，不泄露未发布内容。**〔v1.1〕** 游戏已发布但当前语言内容未发布时，该语言的详情页返回 404。
5. **外站运行错误**：本站无法控制外站加载，不声称一定能玩；访客可以回到本站，通过版权 / 纠错联系渠道反馈。
6. **请求异常**：列表加载失败时提供重试，不展示伪造的列表；参数不合法时给出明确提示，不无限重试；浏览器后退时保持原有的查询条件和页码。
7. **响应式**：移动端的搜索和筛选可以折叠，但必须能操作到；桌面和手机的内容、发布状态保持一致。不需要 App、登录弹窗或全屏离站确认。

## 06 热门快照与内容运营

**已验证事实（沿用 v1.0 研究记录，本次未重新抓取）**：CrazyGames 的 `/hot` 页面描述的是过去 24 小时热度上升。研究快照读取时间为 2026-11-08 16:21（UTC+8），CDN 缓存约 59 分钟；前 20 项是当时页面的展示顺序，不是累计玩家排行，平台也没有公开每款游戏的游玩量。本文不把它称为当前持续更新的榜单。

1. 编辑推荐和热门快照分成两种数据：编辑推荐由 `featured` 和 `editorialOrder` 控制；热门快照是独立的批次和有序条目，不因编辑排序而改写。
2. 快照需要记录 `snapshotId`、`sourceURL`、`sourceFetchedAt`、`sourceCacheNote`、榜单定义、**`observedRegion`（采集时所在地区 / 网络，如 `TW`）〔v1.1 新增〕**、审核状态和条目 `position`。只接受映射到已发布游戏的条目；有缺项时保留原 `position`，不重新编号，避免造成官方名次的错觉。
3. 过期阈值为 `sourceFetchedAt` 之后 48 小时，以服务端时间判断。超过阈值立即从首页移除；`/hot` 仍可展示最近一次已审核的快照，并明确标注"历史快照，已超过 48 小时未更新"。没有已审核快照时，`/hot` 显示说明和游戏目录入口，不生成榜单。
4. **〔v1.1 修订〕时间展示**：持久化统一用带时区的 ISO 8601。前台按当前语言的格式展示绝对时间，并明确标出时区（如 `2026-11-08 16:21 UTC+8` / `Nov 8, 2026, 16:21 UTC+8`）。热门页必须写出采集时间，不能只写"今日热门"。统计按"运营时区"计日，默认 `Asia/Taipei`，可以配置。
5. **〔v1.1 新增〕地区差异**：CrazyGames 的热门内容可能因地区或语言不同。快照对所有语言站共用一份，热门页注明"采集地区：{observedRegion}"；P0 不按语言分别维护快照。
6. **〔v1.1 修订〕** 快照由爬虫每 6 小时自动生成并默认自动发布（第 22.9 节）；管理员可以改为人工审核。爬虫停止或被封时，48 小时过期规则照常生效，宁可隐藏，也不假装实时。运营仍然每周至少人工复核一次已发布条目。
7. **〔v1.1 修订〕** 需求方决定用定时爬虫同步 CrazyGames 数据，并已知悉平台条款禁止自动化采集（第 22.1 节）。爬虫拿到的描述、FAQ、图片、评分都不公开展示；每条公开内容仍以人工核实和原创摘要为主。
8. **〔v1.1 修订〕** 游戏封面默认直接引用 CrazyGames 图片 CDN 上该游戏的 16:9 封面（第 22.12 节），不下载到本站；本站上传的封面和截图仍要逐张留存权利证据。图片加载失败时回退到本站生成的封面。不从网络上搜图补图。

### 7.1 发布门禁〔v1.1 修订：拆成游戏级和语言级〕

**游戏级门禁**（任何语言发布都要满足）：

- 共享必填字段完整；主类别和标签有效；
- 用到的素材都是原创或已有许可且记录齐全，或者显式选择了通用占位；
- 链接符合白名单，并经管理员确认可用；
- `sourceFetchedAt` 和 `linkCheckedAt` 距离发布操作都不超过 7 天。门禁只管这一次发布 / 重新发布，过了 7 天不会自动下架，但后台会提示待复核。

**语言级门禁**（每个语言单独判断）：

- 该语言的必填字段完整，长度符合第 08 节的限制；
- 该语言的 `contentReview=approved`；
- 引用到的类别和所有标签在该语言下都有显示名。

一次发布中，只有满足语言级门禁的语言会上线，其余语言保持原状。批量导入的默认审核状态一律是 pending。

关闭 CTA、下架条目、停用快照属于立即生效的运营操作，必须单独确认并记录；普通修订保存后不改变线上版本。发布或下架后，公开 API、页面和缓存最迟 60 秒内保持一致。

## 08 数据模型与验证

一期建议使用持久化的结构化存储，数据库或等效实现由开发方选择。以下是逻辑字段契约，不强制物理表结构。公开响应只返回已发布版本和必要的展示字段，不包含审核凭据、管理员信息或内部备注。

**〔v1.1 修订〕** 字段分为两类："共享字段"在所有语言中一致；"语言字段"按 `locale` 各存一份，放在 `GameLocale` 里。原 `zhAlias` 改为 `GameLocale.alias`。

### 8.1 Game（共享字段）

| 字段 | 类型、限制与用途 |
| --- | --- |
| `id` / `slug` | `id` 是不可变的 UUID；`slug` 在本站全局唯一，由小写字母、数字和连字符组成，长度 1–100，所有语言共用。发布后 slug 不修改，一期不做别名跳转 |
| `name` | 官方游戏名，必填，1–150 字符，所有语言都显示这个名字 |
| `developer` 〔v1.1 新增〕 | 开发商名称，可选，0–150 字符；由爬虫预填（第 22.6 节），详情页展示 |
| `primaryCategory` / `tags` | 主类别恰好 1 个，取自 15 类字典；`tags` 是标签 slug 数组，最多 8 个，不重复。不得因为游戏名含 `.io` 就自动归类 |
| `platform` / `externalURL` | **〔v1.1 修订〕** `platform` 是枚举，P0 只有 `crazygames` 一个值（以后可以扩展其他平台，各平台各有一套白名单规则）；`externalURL` 是规范化后的白名单 URL，全局唯一，规则见下文；同一款游戏不能因为有多个名字而重复建档 |
| `deviceSupport` / `evidence` | 枚举 `unknown` / `desktop` / `mobile` / `both`，默认 `unknown`；不是 `unknown` 时必须附上公开的证据 URL 和 `checkedAt`，不能从网页是否响应式来推断游戏支持手机 |
| `sourceURL` / `sourceFetchedAt` | 必填，来源链接和带时区的 ISO 时间，用来描述游戏事实的依据，不是授权凭证。时间不能晚于服务端当前时间。来源变更需要重新审核 |
| `cover` / `screenshots` | 封面可以为空；截图最多 5 张，可以为空。每项包含本地 `assetId`、`rightsType`、`rightsEvidenceRef`、`reviewState`；**〔v1.1〕** 图片 `alt` 文本按语言存在 `GameLocale.mediaAlt` 里。来源 URL 不等于许可 |
| 素材权利 | `rightsType` = `original` / `licensed` / `unknown`；`unknown` 不能用于公开展示。许可凭据只在后台可见，记录许可范围和核验备注。通用占位图是本站内置的原创资源，不必每条单独上传 |
| 发布与审核 | `status` = `draft` / `published` / `unlisted`；`materialReview` = `placeholder` / `approved` / `pending` / `rejected`。（`contentReview` 移到语言字段里）审核不等于事实已被自动核实 |
| 链接状态 | `linkStatus` = `unchecked` / `valid` / `suspect` / `invalid`，另有 `linkCheckedAt`、`linkCheckMethod`、`linkCheckNote`；`valid` 需要人工确认打开的是目标游戏页。`suspect` 或 `invalid` 时禁止出站；`unchecked` 时禁止发布 |
| 编排与时间 | `featured` 布尔值，默认 false；`editorialOrder` 非负整数，默认 1000；`createdAt`、`updatedAt`、`revisionVersion` 由服务端维护 |

### 8.2 GameLocale（语言字段）〔v1.1 新增〕

每个 `(gameId, locale)` 一条，`locale` 必须在 `SUPPORTED_LOCALES` 里。长度按 Unicode 码点计算。

| 字段 | `zh` 限制 | `en` 限制 | 说明 |
| --- | --- | --- | --- |
| `alias` | 可选，0–100 | 可选，0–100 | 本地化别名，参与该语言的搜索（原 `zhAlias`） |
| `summary` | 发布必填，20–120 | 发布必填，40–300 | 原创一句话说明，用于卡片和 meta description。禁止直接搬运第三方的长文 |
| `description` | 发布必填，50–3000 | 发布必填，100–5000 | 纯文本，原创简介 |
| `controls` | 可选，0–1000 | 可选，0–2000 | 没有证据时留空，前台显示"操作信息待核实" / "Controls not yet verified"，不靠猜测填写 |
| `mediaAlt` | 每张已用图片 1–150 | 每张已用图片 1–150 | 按 `assetId` 对应 |
| `contentReview` | `pending` / `approved` / `rejected` | 同左 | 每个语言独立审核 |
| `translationMethod` | `original` / `human_translated` / `machine_assisted` | 同左 | 只用于后台和审核，前台不展示 |
| `firstPublishedAt` / `publishedAt` | 服务端维护 | 服务端维护 | "最近收录"按当前语言的 `firstPublishedAt` 排序 |

> 注：`zh` 的 `summary` 由 v1.0 的 20–300 收紧为 20–120 字，因为中文卡片一句话说明超过 120 字会撑破卡片；`en` 的上限按英文字符密度放宽。这一条需求方可以改回原值。

### 8.3 其他实体

| 实体 | 字段 |
| --- | --- |
| Category | 固定的 `slug`、各语言的 `name`（`names: {en, zh}`）、官方来源 URL、`sortOrder` |
| Tag | 唯一的 `slug`、各语言的 `name`、`active`。停用的字典值不能用于新发布 |
| HotSnapshot / Item | 批次包含 `sourceURL`、`sourceFetchedAt`、`cacheNote`、`definition`、`observedRegion`〔v1.1〕、`reviewState`、`active`；条目包含 `gameId` 和正整数 `position`，同一批次内 `gameId` 和 `position` 各自唯一 |
| Audit / Revision | 对象、版本、操作人、时间、变更摘要和内部审核依据；前台不返回，导出时默认排除私有附件。一个 Revision 包含共享字段和全部语言字段 |

### 8.4 外链白名单（P0 仅 `platform=crazygames`）

一期使用严格的白名单：

- 用标准 URL 解析器解析；协议必须是 `https`；hostname 必须正好是 `www.crazygames.com`；不能带用户名 / 密码；只允许默认的 443 端口；
- 路径必须匹配 `/game/` 后接一段游戏 slug，只允许字母、数字和连字符；禁止编码斜杠、反斜杠、点段和多余的路径；
- 去掉结尾斜杠，删除 query 和 fragment 后保存，主机名转小写；
- 拒绝 `crazygames.com.evil.example`、其他子域名、短链、非 `/game/` 的链接和自定义跳转参数。原始 URL 带凭据或结构不合法时直接拒绝，不尝试修复；
- **〔v1.1 新增〕** 数据库只存英文地址 `externalURL`；各语言的 CTA 链接按第 22.8 节的映射表派生，路径允许 `/{cgLocale}/game/{slug}`，`cgLocale` 必须在固定列表里。CrazyGames 没有中文站，所以 P0 的 `en`、`zh` 都指向 `/game/{slug}`；
- P0 不提供任何"跳转到任意 URL"的接口。

来源链接是 https 的公开证据 URL，只用于展示和人工审核。**〔v1.1 修订〕** 服务端只有爬虫模块会访问外部地址，而且只访问第 22.4 节列出的 `www.crazygames.com` 四类地址；导入文件里的 `sourceURL` 仍然不自动访问。授权记录不能作为公开数据泄露；不存储玩家的账号、邮箱、身份证件或支付资料。

## 09 导入契约与候选种子

**〔v1.1 修订〕** 一期 P0 只支持 UTF-8 JSON 导入，文件最大 1 MB，每批最多 200 条。根对象包含 `schemaVersion: 1` 和 `games` 数组（v1.0 的扁平字段格式作废，因为还没有实现，不需要兼容）。

```json
{
  "schemaVersion": 1,
  "games": [
    {
      "name": "Bloxd.io",
      "slug": "bloxd-io",
      "primaryCategory": "io",
      "tags": ["multiplayer", "building", "3d"],
      "externalURL": "https://www.crazygames.com/game/bloxdhop-io",
      "sourceURL": "https://www.crazygames.com/game/bloxdhop-io",
      "sourceFetchedAt": "2026-11-08T16:21:00+08:00",
      "locales": {
        "en": { "alias": "", "summary": "…", "description": "…", "controls": "" },
        "zh": { "alias": "…", "summary": "…", "description": "…", "controls": "" }
      }
    }
  ]
}
```

- 每条的必填字段：`name`、`primaryCategory`、`externalURL`、`sourceURL`、`sourceFetchedAt`。可选字段：`slug`、`tags`、`locales`（以及其中的 `alias`、`summary`、`description`、`controls`）。`locales` 的键必须是 `SUPPORTED_LOCALES` 里的值。
- 状态、审核、排序和内部 id 都不能通过导入直接设置。
- 没有给出 `slug` 时，系统根据名称生成安全的 slug，冲突时加一个短的唯一后缀。
- 导入时 `translationMethod` 默认为 `original`，管理员可以在后台修改。

1. 导入分两步：上传校验预览 → 管理员确认导入。预览逐行显示新增、重复、失败及原因；确认请求带上 `previewId` 和一次性的 `importKey`。重复提交同一个 key 时返回同一批结果，不重复建档。
2. 按规范化后的 `externalURL` 判重。文件内重复和库内重复都跳过并报 `DUPLICATE`，不更新原条目。名称相同但 URL 不同的允许创建，并提示同名、需要人工核实。P0 不做自动覆盖 / upsert。
3. 整个 JSON 无法解析、`schemaVersion` 未知、超出限制或含有未知顶层字段时整批拒绝，不写入。单行的非法类别、URL 或时间等返回 `INVALID_ROW` 并跳过；其余合法行在确认后创建草稿，结果明确标为部分成功。
4. 行字段使用白名单，未知字段标为错误；同一批的合法条目原子写入，数据库故障时整体回滚本次的合法条目。冲突发生时重新返回逐行结果，不悄悄丢数据。
5. 结果至少包含 `jobId`、行号、`name`、`status`（`created` / `duplicate` / `failed`）、`gameId` 和 `errorCode` / `message`；管理员可以下载 JSON 格式的结果。所有导入内容按不可信的纯文本处理，禁止执行 HTML 或解释公式。
6. 导入不要求草稿已经满足发布要求，原创简介等可以之后补。任何导入的候选都需要人工审核，不能通过导入字段把 `contentReview` 或 `status` 设为已发布。
7. CSV 属于 P1：如果增加，需要有明确的字段映射，并正确处理引号和换行。任何表格导出都要对以 `=`、`+`、`-`、`@`、制表符或回车开头的单元格加安全前缀，防止公式注入。不能因为支持 CSV 就取消服务端校验。

## 10 页面数据与接口契约

一期建议按下面的 HTTP 语义实现；可以用服务端渲染或其他技术，但对外的页面数据、权限和错误行为必须等价。不限定框架、云厂商、数据库，也不要求独立微服务。开发方先提交简短的技术方案和部署成本假设，确认后再实施。**〔v1.1 新增〕** 已确定的技术栈（Go 后端、Next.js 前端、PostgreSQL、Docker + VPS + Cloudflare CDN）和配套建议见 [TECH-STACK.md](TECH-STACK.md)。

**〔v1.1 修订〕** 所有公开接口都必须带 `locale` 参数，取值必须在已上线语言里，否则返回 400。

| 接口 / 数据入口 | 契约 |
| --- | --- |
| `GET /api/games` | 参数：`locale`、`q`、`category`、`tag`、`sort`、`page`、`pageSize`。`page` 从 1 开始；`pageSize` 默认 24、最大 48；`sort` 取 `editorial` 或 `newest`。响应：`items`、`total`、`page`、`pageSize`、`totalPages`、`appliedFilters`。只返回在该语言下已发布的游戏 |
| 查询规范 | `q` 去掉首尾空白后为空时等于没有关键词，最长 80 字符；按字面子串匹配，不当作 SQL 通配符。`category` 和 `tag` 精确匹配 slug，未知值返回 400。`page` 超过总页数时返回空的 `items` 和真实的 `total`，不回退，也不伪造结果。`total=0` 时 `totalPages=0` |
| `GET /api/games/{slug}?locale=` | 返回已发布版本在该语言下的详情，以及派生字段 `outboundAllowed`、`availableLocales`〔v1.1〕。草稿、未知 slug，或该语言未发布时返回 404；下架返回 410；不返回内部审核材料 |
| `GET /api/games/{slug}/related?locale=` 〔v1.1 新增〕 | 按第 18 节规则返回最多 6 条；可以合并进详情接口一起返回 |
| `GET /api/categories`、`GET /api/tags` | 只返回在该语言下有已发布游戏的有效项和已发布数量；管理接口另外提供完整字典。首页精选按固定排序获取，最多 12 条 |
| `GET /api/hot?locale=` | 返回最近一个 active 且 approved 的批次及可见条目，包括 `snapshotId`、`sourceFetchedAt`、`observedRegion`、`definition`、`stale` 和 `position`；没有映射或已下架、该语言未发布的条目过滤掉，且不重新排 position。没有快照时返回 `snapshot=null`，不造数据 |
| `POST /api/events` | 只接收白名单里的事件和字段；202 表示已接收，不承诺一定入库。不会因为计数暴露用户信息。可以返回 400 / 429，前端不能因此阻止离站 |
| `/api/admin/games` | 认证后 `GET` 列表、`POST` 草稿、`PATCH` 修订；更新时带上 `revisionVersion`，冲突返回 409。服务端过滤禁止写入的字段，错误返回 400 / 422 |
| 管理员发布操作 | `POST /api/admin/games/{id}/publish`（请求体带 `locales` 数组，可选，默认为所有通过门禁的语言）、`/unlist`、`/disable-outbound`；`publish` 校验全部门禁。下架和关闭 CTA 要记录原因；可以恢复，但必须重新审核发布 |
| 管理员预览 / 字典 / 快照 | 认证后按语言获取指定 revision 的预览；分类标签的写操作和快照的创建 / 审核 / 停用只限管理员。预览和后台响应带 `Cache-Control: no-store` |
| 管理员导入 / 统计 | `POST /api/admin/imports/preview`、`/commit`；`GET /api/admin/imports/{id}`；`GET /api/admin/stats?from=&to=&gameId=&locale=`。统计区间按运营时区的日界计算，最长 90 天 |

统一错误格式为 `code`、`message`、`fieldErrors`、`requestId`，禁止返回堆栈或数据库细节；错误码枚举见附录 A。所有边界、排序、长度、发布门禁、链接和权限校验都在服务端执行，前端只做即时提示。公开缓存不能混入管理员预览的数据；任何写操作都不用 GET。

## 11 外链策略与统计隐私

| 事件 / 字段 | 一期建议定义 |
| --- | --- |
| `game_view` | 只在已发布的详情页成功显示时触发；同一标签页的一次路由进入只记 1 次，重新加载算新的浏览；列表曝光、预览或 404 不触发 |
| `outbound_click` | 用户每激活一次有效的详情 CTA 触发 1 次；鼠标左键、键盘，以及能捕获到的中键打开都计入。通过右键菜单复制或打开链接等可能漏记，不承诺完整计量 |
| `related_click` 〔v1.1 新增〕 | 用户每点击一次相关游戏卡片触发 1 次，`gameId` 是被点击的游戏，另外带 `sourceGameId`（当前详情页的游戏） |
| 共同字段 | `eventId`（随机 UUID）、`eventName`、`gameId`、`pageType`、`pagePath`（本站路径，不带 query）、**`locale`〔v1.1〕**、`occurredAt`（客户端时间，带时区）、`receivedAt`（服务端时间）、`placement`、`entrySource`。不接受任何附加字段 |
| `placement` | `game_view` 为 `detail_page`；`outbound_click` 为 `detail_primary`；`related_click` 为 `detail_related`。以后新增卡片出站时必须用另一个 placement，不能和详情页点击率混算 |
| `entrySource` | 枚举 `home_featured`、`home_hot`、`category`、`search`、**`related`〔v1.1〕**、`direct_or_unknown`；通过站内导航的上下文传递。不保存完整的外部 referrer、搜索词、UTM 或任何 URL |
| 去重与汇总 | 服务端按 `eventId` 去重，只防止同一事件因传输重试被记两次，不把同一个人的多次点击合并；按 `receivedAt` 换算成运营时区的日期汇总。计数是事件次数，不是人数 |
| 隐私与留存 | P0 不设用户 ID，不用跨站 cookie 或指纹，不统计 UV。原始事件建议保留 30 天，日聚合保留 90 天，到期清除。基础设施日志要单独限制并脱敏，不把 IP / 完整 UA 放进产品事件库 |
| 日 UV（P1） | 取得合规方案确认后才考虑；如果使用短期的第一方随机标识，需要公开期限、拒绝方式和删除策略，并说明跨设备不去重；P0 不得用 IP 推算 UV |

**出站实现**：使用直接指向已验证 `externalURL` 的语义化链接，`target=_blank`，`rel="noopener noreferrer"`，不经过任何 URL 重定向器。普通点击、键盘激活和能捕获的中键动作用 `sendBeacon` 或 `keepalive` 尽力发送事件；禁止 `await` 统计请求、阻止默认导航，或先请求广告 / 统计接口再开页面。禁止自动重试造成重复计数。

**归因取舍**：`noreferrer` 默认不向目标平台发送本站来源，平台那边可能无法识别导流站；本站仍然可以记录本站上下文中的来源和点击。这样做保护了隐私，但不满足外站返佣或逐用户归因。不得一边这样设置，一边声称平台一定能识别本站流量；如果以后合作需要归因，另行确认链接参数、隐私政策和出站策略。

一期建议在浏览器设置了 `DNT=1` 或 `GPC=true` 时停止发送产品统计事件，页面展示和离站照常。由实现方提供最小必要的防滥用限制，但不靠跟踪用户来提高统计准确性。报表注明屏蔽、离线、浏览器行为和机器人都可能影响计数。

**〔v1.1 新增〕国际访客合规**：P0 不设置任何非必要的 cookie 或本地存储，不收集个人数据，所以默认不需要 cookie 同意横幅。基础设施日志里的 IP 属于个人数据（GDPR 口径），隐私页要写明保存期限和用途。上线目标地区如果包括欧盟 / 英国 / 加州等，由需求方确认是否需要额外的法务审阅。

## 12 安全、SEO 与体验要求

1. **安全**：后台使用成熟的认证组件，HTTPS，会话 cookie 设置 HttpOnly / Secure / 合适的 SameSite，有 CSRF 防护、登录限速，退出后会话失效。管理员凭据通过部署环境安全配置，禁止写进源码、页面或导入文件。P0 建议 30 分钟无操作就失效，管理员更换凭据后撤销旧会话。
2. **内容安全**：所有编辑和导入的文本输出时都要转义，不支持任意 HTML / 脚本。SQL 等存储操作要参数化。只有已认证的管理员可以上传图片，限制为 JPEG / PNG / WebP、单张 2 MB，检验实际文件内容并重新编码；禁止 SVG、可执行文件和任意远程 URL 代理。
3. **防开放跳转与 SSRF**：不提供任意 target 参数的跳转；服务端不自动访问导入的来源 URL。**〔v1.1 修订〕** 爬虫的目标地址由代码按固定规则拼出（主机固定为 `www.crazygames.com`），不接受任何外部输入的 URL；每一跳重定向都重新校验主机，阻断私网地址和非标准端口，不跟随跨主机重定向。
4. **SEO**：详情页、有内容的分类页和首页提供可索引的 HTML、独立的 title 和 description，以及绝对 canonical；站点域名未定时通过配置生成。sitemap 只收录已发布的可索引详情页、有内容的分类页和主要静态页，不包括后台、草稿、下架、搜索或筛选参数页。
5. **索引规则**：`/{locale}/games` 搜索 / 筛选参数页、空结果页、空类别、预览、后台都设 noindex；有内容的分类落地页可以被索引。分类分页使用各页自身的 canonical，不把不同内容都指向首页。robots 不是鉴权手段。
6. **多语言 SEO〔v1.1 新增〕**：
   - 每个可索引页面用 `<link rel="alternate" hreflang>` 列出**该页面实际已发布**的所有语言版本（`en`、`zh-Hans`），外加 `hreflang="x-default"` 指向 `/` 对应路径；hreflang 必须双向一致。
   - canonical 指向当前语言版本自身，不跨语言 canonical。
   - `<html lang>` 与当前语言一致（`en`、`zh-Hans`）。
   - sitemap 按语言拆分（`/sitemap-en.xml`、`/sitemap-zh.xml`）加一个索引文件，条目带 `xhtml:link` 互指。
   - 某个语言上线前（不足 10 款，见第 03 节）整站该语言 noindex，并且不进 sitemap。
7. **宣传边界**：不伪造评分、玩家量、平台背书或实时热度；不标注不存在的聚合评分结构化数据。可以使用真实的基础网页结构化信息，不冒充 CrazyGames 官方站。
8. **性能建议目标**：生产构建、固定测试环境，模拟移动设备 390×844、Fast 4G、4 倍 CPU 降速，冷缓存跑 3 次取中位数；首页、列表和详情页 LCP ≤ 2.5 秒、CLS ≤ 0.1。真实 INP ≤ 200 ms 是上线后样本足够时的观察目标，不作为已测结果。
9. **资源策略**：封面使用固定宽高比（16:9，见第 20 节）、适当压缩，在首屏之外懒加载；首屏不下载游戏本体或第三方 SDK。统计和图片失败不能影响核心内容阅读和离站。**〔v1.1〕** 正文使用系统字体栈（含 CJK 回退）；标题允许使用一个自托管的拉丁展示字体（构建时下载并由本站提供，只取 Latin 子集，`font-display: swap`），不产生运行时的第三方字体请求。
10. **响应式与无障碍**：360px、768px、1440px 视口下页面不出现横向溢出；核心功能可以用键盘操作，焦点可见，链接名称能说明用途，正文对比度至少 4.5:1；图片有 alt，纯装饰图用空 alt；点击目标建议至少 44×44 CSS 像素。
11. **浏览器默认**：验收时使用最新稳定版的 Chrome 和 Safari，桌面和手机各一组，版本号写进报告。自动化覆盖不到的设备用手动截图补充证据，不能只凭设计稿宣称兼容。
12. **运行保障**：开发、测试和生产的配置隔离，备份内容数据和素材权利记录（频率见第 21 节）；交付一条可以重复执行的恢复路径，并在测试环境验证过。部署日志不记录会话密钥、明文凭据或完整的个人数据。
13. **国际化实现〔v1.1 新增〕**：界面文案全部放在语言资源文件里，代码中不写死任何语言文本；新增一种语言只需要修改配置 `SUPPORTED_LOCALES`、补全资源文件、类别 / 标签译名和法律页内容，不改业务代码。日期、数字按当前语言用 `Intl` 格式化。

## 13 可重复 E2E 验收

一期建议把可重复的端到端测试作为交付证据，不接受"以后补测试"作为通过条件。使用固定的测试数据、固定的快照时间和可控的统计 / 外链失败模拟；每项都保留 Given / When / Then 对应的脚本、报告、关键截图和失败 trace。单元测试可以由实现方自行补充，但不能代替下面的业务验收。

| 编号 / 场景 | Given → When → Then |
| --- | --- |
| E01 浏览与分类 | 已有 10 款 published、2 款 draft、1 款 unlisted → 打开首页和公开列表 → 只出现 10 款已发布数据；15 类字典都存在，零发布游戏的类别不出现在导航里 |
| E02 搜索与组合筛选 | 存在带英文名和标签的固定条目 → 输入大小写混合的关键词，并选择类别和标签 → 按 AND 匹配，URL 同步；清除筛选后恢复默认；浏览器后退时恢复条件和页码 |
| E03 排序分页 | 准备 30 条记录，其中部分 `editorialOrder` 相同 → 逐页查询并切换排序 → 每页 24 条，总数正确，没有重复或遗漏，按 id 打平的规则确定；切换条件后回到第 1 页；越界页返回空，而不是重复第一页 |
| E04 搜索空态 | 输入不存在的关键词 → 提交 → 显示 0 个结果和清除入口，且 noindex；不自动添加相似游戏；未知类别页 404，已知的空类别 200 且 noindex |
| E05 详情与无图 | 已发布游戏没有封面、`controls` 为空、设备为 unknown → 打开详情页，并模拟图片 404 → 显示自制占位图，布局不塌陷；能看到"操作待核实"和"设备未确认"，没有虚构的适配信息或评分 |
| E06 正常出站 | 详情页有效，统计服务正常 → 点击或用键盘激活 CTA → 新标签页打开精确的白名单游戏 URL，原页面保留；`noopener noreferrer` 存在；一次操作只产生一个 `outbound_click`，`game_view` 不重复 |
| E07 统计失败仍离站 | 事件接口离线、超时或返回 429 → 激活 CTA → 不等待，也不阻止默认离站；没有阻断弹窗，仍然打开目标；不会循环重试产生重复事件 |
| E08 已知失效 / 待核 | 线上游戏的 `linkStatus` 改为 suspect 或 invalid → 打开详情 → 提示不可用，CTA 禁用且不产生离站事件；单次 403 只进入待核实流程，不自动删除游戏 |
| E09 草稿与下架 | 存在草稿、下架游戏和不存在的 slug → 直接访问公开 API 和 URL → 草稿和不存在的 slug 返回 404，下架返回 410，没有 CTA；列表和 sitemap 没有泄露；后台预览不会被缓存给访客 |
| E10 后台鉴权 | 未认证 / 无权限的会话 → 调用增删改、导入、预览、发布和统计接口 → 分别返回 401 / 403，且没有写入；只隐藏按钮不算通过 |
| E11 草稿修订与发布 | 已有发布版本 A → 修改为 B 并保存但不审核 → 公开内容仍然是 A，管理员可以预览 B；缺少授权或核实过期时发布返回 422；满足全部门禁后发布 B，60 秒内公开内容一致 |
| E12 导入与幂等 | 20 条候选，另加重复 URL、非法类别和恶意 URL → 预览后确认 → 合法项只生成草稿，逐行报告准确；重复提交同一个 `importKey` 不会重复建档，已有内容不被覆盖；格式错误时整批不写入 |
| E13 URL / 文本安全 | 输入恶意子域、http、带凭据、编码斜杠、重定向参数和脚本文本 → 保存 / 预览 → URL 按规则拒绝或规范化去参，脚本始终显示为文本；没有开放重定向，也没有脚本执行 |
| E14 热门时效 | 固定快照里有缺失或已下架的条目 → 时间推进到 48 小时后 → 首页的热门模块隐藏，`/hot` 显示历史标识和原始位置；编辑推荐不受影响，也没有新编造的名次 |
| E15 分类标签与名义 | Growden.io 主类别为 sim，Bloxd.io 为 io → 浏览和筛选 → 按明确的主类别归属，名字里的 `.io` 不覆盖主类别；tag 和 category 互不混写 |
| E16 统计去重与隐私 | 用相同 `eventId` 发送两次，再跨运营时区日界发送新事件 → 查看报表 → 重复事件只记一次，按 `receivedAt` 的运营时区日期汇总；不存个人标识、完整 referrer 或搜索词；开启 DNT / GPC 时不发事件，但仍然可以离站 |
| E17 SEO 与 404 | 抓取首页、已发布详情、有效类别、搜索、草稿和未知路径 → 检查响应和源码 → canonical 正确，公开内容可读，noindex 和 sitemap 符合规则；未知路径返回真实 404，不是全站 200 |
| E18 体验与交付恢复 | 指定视口、浏览器和性能环境 → 完成浏览 / 筛选 / 出站和后台发布，再从备份恢复测试数据 → 没有溢出，键盘可以操作到，性能按目标记录；恢复后目录和素材凭据一致 |
| **E19 语言跳转与切换〔v1.1〕** | 按第 4.2 节示例表逐行发请求（含 q 值排序、`zh-TW`、无请求头、非法请求头、带 query 的不带前缀路径）；再带 `Accept-Language: zh-CN` 访问 `/en/games/{slug}` 并点击语言切换 → 每行的状态码和 `Location` 与示例表一致，`Location` 保留原 query；跳转响应带 `Vary: Accept-Language`、没有 `Set-Cookie`，且没有用 301；带前缀的 `/en/games/{slug}` 不被请求头改写，返回 200 英文页；切换后到达 `/zh/games/{slug}`，目标语言没有该游戏时到达 `/zh/`；`/xx/` 和 `/foo` 返回 404；`/api/*`、`/admin/*`、`/sitemap*.xml` 不跳转。另用两个不同 `Accept-Language` 经过 CDN 先后请求 `/`，确认没有互相串缓存 |
| **E20 按语言发布〔v1.1〕** | 游戏 G 的 `en` 已审核、`zh` 为 pending → 发布 → `/en/games/G` 是 200，`/zh/games/G` 是 404；`zh` 的列表、搜索、sitemap、热门都不出现 G；`en` 详情页的 hreflang 不包含 `zh`。之后审核 `zh` 并再次发布 → 60 秒内 `zh` 可以访问，双方的 hreflang 互指 |
| **E21 搜索不跨语言〔v1.1〕** | G 的 `zh.alias` 是"方块世界"，`en.alias` 为空 → 在 `/zh/games?q=方块` 和 `/en/games?q=方块` 分别搜索 → 前者命中 G，后者 0 个结果；两种语言都可以用官方英文名搜到 |
| **E22 相关游戏〔v1.1〕** | 固定 10 款游戏（类别和标签重叠程度已知，其中 1 款下架、1 款当前语言未发布、1 款 linkStatus=invalid） → 打开某款详情 → 相关列表和第 18 节算法的预期顺序完全一致，最多 6 条，不含自身、下架、未发布或不可出站的条目；没有候选时模块隐藏；点击产生一次 `related_click`，并带 `entrySource=related` 进入目标详情页 |
| **E23 分享元数据〔v1.1〕** | 抓取一款有授权封面的详情页和一款无封面的详情页（两种语言） → 检查 head → `og:title`、`og:description`、`og:url`、`og:image`、`og:locale` 及 `og:locale:alternate`、`twitter:card` 都正确；无封面时使用默认分享图；不出现未授权的第三方图片 URL |
| **E24 爬虫规则与熔断〔v1.1〕** | 用模拟的 CrazyGames 服务（见表后说明），依次返回 robots 禁止路径、带 `Retry-After` 的 429、人机验证页 → 运行爬虫 → 从不请求被禁止的路径；请求串行且间隔 ≥ 2 秒；UA 符合第 22.4 节；遵守 `Retry-After`；达到阈值后终止本次运行并告警；连续 3 次终止后爬虫自动关闭；跨主机重定向不跟随 |
| **E25 来源目录与收录〔v1.1〕** | 模拟 sitemap 有 5 款游戏及其详情页 → 跑目录同步和补全，再在后台点"收录为草稿" → 来源目录有 5 条；草稿字段与第 22.6 节映射一致；草稿不出现在公开页面和 API；CrazyGames 的描述、FAQ、图片 URL、评分在任何公开 HTML 和 API 响应里都不存在 |
| **E26 自动维护与变更〔v1.1〕** | 4 款已发布游戏，模拟服务分别返回 404、`status` 非 PUBLISHED、改了名字、503 → 跑已收录游戏检查 → 前两款 `suspect` 且 CTA 禁用、没有自动下架；改名的那款进入"变更待复核"，公开内容不变；503 的那款状态不变 |
| **E27 热门快照自动生成〔v1.1〕** | 模拟 `/hot` 返回 20 项，其中部分没有收录 → 跑热门任务 → 自动发布快照，只含已发布游戏且保留原位置；关闭自动发布后新批次为待审核；停止爬虫并把时钟推进 48 小时 → 首页热门模块隐藏 |

**模拟 CrazyGames 服务的要求〔v1.1〕**：E24–E27 不访问真实的 CrazyGames。模拟服务使用从真实页面保存下来的 HTML 和 sitemap 片段作为样本，路径、robots 规则、状态码含义、`__NEXT_DATA__` 结构都要和真实站点一致；样本在技术验证阶段采集一次，随测试代码交付。

第三方外站不能作为完全受控的测试环境：E06 在测试中验证即将打开的真实 URL 和链接属性，可以拦截导航，生成可重复的证据；上线前由人工点开至少 3 个目标，确认落到了对应的游戏页。外站的广告、登录、地区限制和游戏实际运行都不属于本站能保证的验收结果。

**通过标准**：全部 P0 场景通过，阻断性 / 高严重度缺陷清零；任何没通过的项要列出复现步骤、影响和处理方式，不用"基本完成"代替。性能目标如果受实际部署条件限制，需要需求方明确接受偏差后才算交付，不得把没测过的值写成已达成。

## 14 实施顺序与交付清单

1. **第一步：锁定默认基线**——确认暂用名称、**首发语言（P0 默认 `en` + `zh`）〔v1.1〕**、目标市场、P0 范围和上线前的权利责任；开发方提交技术方案、部署方式和成本假设。不虚构工期或人天。

## 17 多语言与国际化〔v1.1 新增〕

### 17.1 原则

1. **内容按语言分别发布**：某个游戏在某个语言下"存在"的条件是：游戏已发布，并且该语言的内容审核通过。不做跨语言回退显示（例如不在英文页显示中文简介），避免出现混杂语言的页面和重复内容。
2. **共享事实，本地化表达**：游戏名、外链、类别、标签、素材和设备证据只有一份；简介、操作、别名和图片 alt 按语言各写一份。
3. **扩展零代码**：语言列表由配置驱动（见第 12.13 条）。
4. **不自动翻译后上线**：机器翻译只能用于生成草稿，必须人工审核。

### 17.2 语言清单

| locale | 路由前缀 | `html lang` / hreflang | 界面名 | 优先级 |
| --- | --- | --- | --- | --- |
| en | `/en/` | `en` | English | P0（同时是 x-default 的落地语言） |
| zh | `/zh/` | `zh-Hans` | 简体中文 | P0 |
| ja / es / pt-BR / zh-Hant 等 | `/ja/` … | 对应 BCP 47 | 自称 | P1，需求方按流量和运营能力逐个确认 |

### 17.3 翻译范围

| 内容 | 谁负责 | 说明 |
| --- | --- | --- |
| 界面文案（导航、按钮、空态、错误提示、CTA 说明） | 开发方提供 `en`、`zh` 资源文件，需求方审校 | 不能有写死的文案 |

## 18 推荐与相关游戏〔v1.1 新增〕

### 18.1 定位

"推荐"在一期中只有两种形式，都是**非个性化、对所有访客相同、可以解释**的：

| 形式 | 优先级 | 来源 |
| --- | --- | --- |
| 编辑精选（首页） | P0（v1.0 已有） | 管理员 `featured` + `editorialOrder` |
| 相关游戏（详情页） | P0 | 本节的规则算法 |
| 专题合集 Collections（如"适合 2 人一起玩"） | P1 | 管理员手工编排，有独立落地页 `/{locale}/collections/{slug}` |
| 首页分类货架（每个有内容的类别各一行，最多 8 款） | P1 | `editorialOrder` |
| 相关游戏人工置顶 | P1 | 每款游戏最多指定 6 个 `pinnedRelated` |

不做：基于浏览历史、点击、设备或地区的个性化推荐；"猜你喜欢"；用站内点击数参与排序（避免被刷，也避免泄露统计数据）。

### 18.2 相关游戏算法（确定性）

对当前详情页的游戏 G 和当前语言 L：

1. **候选集**：所有满足以下条件的游戏 X —— X ≠ G；X 的 `status=published`；X 在语言 L 下已发布；X 的 `outboundAllowed=true`（`linkStatus=valid` 且没有关闭 CTA）。
2. **打分**：`score(X) = 3 × [X.primaryCategory = G.primaryCategory] + 1 × |X.tags ∩ G.tags|`。
3. **过滤**：只保留 `score ≥ 1` 的候选。
4. **排序**：`score` 降序 → `editorialOrder` 升序 → `id` 升序。
5. **截取**：取前 6 个；结果为 0 时隐藏模块。不足 6 个时按实际数量展示，不用无关游戏补位。
6. **缓存**：可以在发布或下架时重新计算并缓存，但必须满足第 07 节"60 秒内一致"的要求。

这个算法不依赖任何用户数据，结果对所有人相同，所以页面可以完整缓存，也能被 E22 完全复现。

### 18.3 展示

- 卡片样式和列表卡片相同，点击进入本站的详情页，不直接出站。
- 进入目标详情页时 `entrySource=related`；点击触发 `related_click`（第 11 节）。
- 模块标题旁边不写"为你推荐"之类暗示个性化的文案。

## 19 内容编写规范与标签字典〔v1.1 新增〕

### 19.1 编写规范（适用于所有语言）

1. **原创**：用自己的话描述玩法，禁止复制 CrazyGames 或开发商的描述（包括翻译后照搬）。可以引用游戏名和必要的专有名词。
2. **只写能核实的**：玩法和操作必须是编辑实际打开游戏页确认过的；不确定就留空，交给前台的"待核实"文案。
3. **禁用表述**：不写"最好玩""第一""全球 xx 万玩家""官方推荐""免费无广告""手机完美适配"之类无法证实的话；不写"在本站玩"。
4. **一句话说明（summary）**：说清楚"玩什么 + 怎么玩 / 亮点"，不以游戏名开头重复；中文 20–120 字，英文 40–300 字符。
5. **简介（description）**：建议按"玩法概述 → 目标 → 特色 / 模式 → 适合谁"组织；纯文本，可以用换行分段，不用 Markdown 或 HTML。
6. **操作（controls）**：每行一条，格式为"按键：动作"，例如 `WASD：移动`。
7. **语气**：中文用简体，客观、口语、不夸张；英文用美式拼写，用第二人称 "you"。
8. **翻译**：是本地化而不是逐字翻译；按键名和游戏内术语保持原文；机器翻译的草稿要逐句校对后才能审核通过。

## 22 CrazyGames 数据同步（定时爬虫）〔v1.1 新增〕

### 22.1 决策与风险

- **决策**：需求方于 2026-11-08 决定，通过定时爬虫从 CrazyGames 公开页面同步游戏数据和热门快照。
- **已知风险**：CrazyGames 服务条款第 6.3 G 条写明 "You will not conduct any systematic or automated data collection activities, including scraping, data mining, data extraction and data harvesting"（2026-11-08 读取）。可能的后果包括 VPS IP 被封、平台要求停止、收到法律函件。需求方已知悉并接受这个风险，风险登记 R1 相应上调（第 21.2 节）。本文不是法律意见。
- **由此带来的设计约束**：爬虫必须可以一键停止；不规避任何封禁或人机验证；请求量尽量小；抓到的数据只有事实性字段可以公开展示。收到平台的停止要求后，24 小时内关闭爬虫并由需求方处理。

### 22.2 已观察到的数据来源

以下是 2026-11-08 单次人工查看的结果。页面结构随时可能变化，以开工时的技术验证为准。

| 来源 | 内容 | 用途 |
| --- | --- | --- |
| `/robots.txt` | 对所有爬虫禁止 `/u/`、`/uid/`、`/search?q`、`/preview/`（包括带语言前缀的版本）；sitemap 指向 `/sitemap-index.xml` | 每次运行前读取并遵守 |

| --- | --- | --- | --- |

### 22.4 抓取规则（控制请求量，不规避封禁）

1. 只访问 `https://www.crazygames.com` 下四类地址：`/robots.txt`、sitemap、`/game/{slug}`、`/hot`。不访问 robots.txt 禁止的路径，不调用站内的内部 API，不加载游戏本体、图片或视频。
2. 串行抓取（并发 1），两次请求间隔至少 2 秒，另加随机抖动；每天请求上限默认 3000，可以配置。
3. User-Agent 固定写明本站名称和联系页面，例如 `PlayTrailBot/1.0 (+https://{域名}/about)`，不伪装成浏览器。
4. 从 VPS 的固定出口 IP 访问。**不使用代理池，不轮换 IP 或 UA，不用无头浏览器或打码服务绕过人机验证**（条款第 6.2 O 条也禁止掩盖身份）。
5. 对方支持 `ETag` / `Last-Modified` 时使用条件请求。
6. 遇到 429 / 503 时遵守 `Retry-After` 并指数退避。同一次运行中累计 5 次 403 / 429，或遇到人机验证页面，立即终止本次运行并告警。连续 3 次运行被终止时，自动关闭爬虫，等待管理员处理。
7. 只跟随同一主机内的重定向，跳到其他主机的一律算失败。
8. 后台提供"暂停爬虫"开关，立即生效；环境变量 `CRAWLER_ENABLED=false` 可以在部署层面关闭。

### 22.5 来源目录与收录流程

- 爬虫的数据写进独立的**来源目录**（`SourceGame`），**不直接进入公开目录**。公开目录仍然只能由管理员收录、审核、发布，第 07 节的发布门禁不变。
- 后台新增"来源目录"页面：可以按名称、分类、标签、开发商、CrazyGames 收录时间、是否支持移动端筛选。每条都有"收录为草稿"按钮，按第 22.6 节的映射预填字段；已经收录的条目链接到对应的游戏。
- 收录生成的草稿和导入的一样：`status=draft`，各语言 `contentReview=pending`，原创简介需要编辑来写。
- 来源目录与公开目录自动关联（1:1）：`game_id` 为空的来源行，当 `https://www.crazygames.com/game/{slug}` 与某游戏的 `external_url` 相等时建立关联；在目录同步、详情补全、任何路径新建游戏以及热门快照映射前执行。热门映射只通过 `game_id` 或 `external_url` 解析，不用本站 slug。
- JSON 导入（第 09 节）保留，作为补充入口。

### 22.8 各语言的外链

- 本站每种语言的 CTA 链接按固定映射表派生，例如本站 `ja` → CrazyGames `/jp/game/{slug}`，`pt-BR` → `/br/game/{slug}`。CrazyGames 没有对应语言时（比如中文），使用英文的 `/game/{slug}`。所以 P0 的 `en` 和 `zh` 都指向 `/game/{slug}`。
- 外链白名单（第 8.4 节）相应扩展：路径可以是 `/game/{slug}`，也可以是 `/{cgLocale}/game/{slug}`，`cgLocale` 必须在固定列表里。数据库里只存 `externalURL`（英文地址），各语言链接在输出时派生。

### 22.9 热门快照自动化

- 每 6 小时抓取一次 `/hot`，按页面顺序取前 20 项，生成一个快照批次：`sourceFetchedAt` 为抓取时间，`observedRegion` 为 VPS 所在地区（配置项）。
- 只保留能映射到本站已发布游戏的条目，保留原来的 position，不重新编号（第 06 节第 2 条不变）。
- 默认自动审核发布（`reviewState=approved`，审核人记为 `system`）。管理员可以关闭自动发布，改成人工审核，也可以停用任何一个批次。
- 爬虫停止后，48 小时过期规则照常生效，首页的热门模块会自动隐藏。

### 22.10 运行记录与告警

- 每次运行写一条 `SyncRun`：任务类型、开始和结束时间、请求数、各状态码计数、新增 / 变更 / suspect 数量、终止原因、解析器版本。
- 以下情况通知运营负责人：运行被终止；一次运行中解析失败率超过 20%（通常说明页面结构变了）；爬虫被自动关闭；24 小时内没有任何成功的运行。
- 后台"同步状态"页面显示最近的运行记录、当日配额用量和爬虫开关。

### 22.12 游戏封面直接引用 CrazyGames 图片〔v1.1 新增〕

- **决策**：需求方于 2026-11-08 决定，公开页面展示 CrazyGames 的游戏封面，方式为直接引用其图片 CDN（热链），不下载、不转存到本站。
- **已核实（2026-11-08 单次请求）**：`imgs.crazygames.com` 不校验 Referer；支持 `width` 参数按需缩放；按 `Accept` 自动返回 AVIF / WebP / JPEG；`Cache-Control` 约 3 年。
- **风险**：封面版权属于开发商或 CrazyGames，展示未经许可；对方可以随时屏蔽外站引用。风险登记 R1 已包含这一项。
- **数据**：`coverSourcePath` 是 CrazyGames 游戏对象里的 `cover` 字段（例如 `evowarsio_16x9/20251003061326/evowarsio_16x9-cover`），由爬虫在收录时预填，也可以在导入或后台手工填写；格式校验 `^[A-Za-z0-9_-]+(/[A-Za-z0-9_.-]+)*$`，最长 200 字符，不能含 `..`。清空就表示不用。
- **URL 规则**：`https://imgs.crazygames.com/{coverSourcePath}?metadata=none&quality=85&width={w}`，`w` 取 320 / 640 / 1280 生成 `srcset`；分享图用 `width=1200&height=630&fit=crop`。只有服务端按这条规则拼 URL，主机固定，不接受外部输入的图片 URL。
- **优先级**：本站上传且权利审核通过的封面 > CrazyGames 封面 > 本站生成的封面。
- **前台要求**：`<img>` 带 `referrerpolicy="no-referrer"`、`loading="lazy"`（首屏主图除外）、固定 16:9 占位；生成封面垫在图片下面，图片加载慢或失败时看到的是生成封面，不出现空白或破图，不产生布局偏移。
- **发布门禁**：CrazyGames 封面不要求本站的权利证据，不影响 `materialReview`。
- **停用**：后台可以对单个游戏清空 `coverSourcePath`；环境变量 `EXTERNAL_COVERS_ENABLED=false` 可以全站停用，此时所有游戏都回退到生成封面（用于收到对方要求时 24 小时内处理）。
